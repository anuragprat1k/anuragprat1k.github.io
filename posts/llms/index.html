Llama Herd#

Llama 4, April ‘25#

  • Architecture
    • MoE, natively multimodal
    • uses interleaved attention layers without position embeddings
    • employ inference time temperature scaling of attention to enhance length generation (called iRoPE)
  • Params - Scout (17B active parameters with 16 experts, 10M context window), Maverick (17B active parameters with 128 experts), Behemoth (288B active parameters) still training. Scout can fit on a single H100 GPU (with Int4 quantization)
  • Data
  • Training
    • Pre-training
      • uses early fusion for multimodal training. Vision encoder is based on MetaCLIP.
      • new training technique called MetaP that allows us to reliably set critical model hyper-parameters.
      • FP8 precision.
      • 30T tokens
      • Mid-training - long context extension using specialized datasets
    • Post-training
      • lightweight SFT -> online RL -> lightweight DPO
      • biggest challenge was maintaining a balance between multiple input modalities, reasoning and conversational abilities. Came up with a curriculum learning strategy.
      • A key learning was that SFT and DPO can over-constrain the model’s exploration. Removed 50% of the data tagged as easy by using Llama as judge. Iterated this stage - filter, train (RL), filter ..

Llama 3, July ‘24#

  • Architecture - Grouped-Query Attention (GQA)
  • Context Length - 128K tokens
  • Tokenizer - vocab of 128K tokens
  • Data
    • 15 trillion tokens, 50% general knowledge tokens, 25% of math and reasoning, 17% code, 8% multilingual
    • on final 40M tokens, linearly annealed the learning rate to 0 and adjusted the data mix to upsample data sources of very high quality. Compute the average of model checkpoints during annealing to produce the final checkpoint
  • Training
    • Pre-training - 16K H100s, 3.8 x 10^25 FLOPS
    • Post-training - SFT, Rejection Sampling, RLHF
      • public instruction datasets alongside 25 million synthetic examples
      • iterative finetuning
      • adopt PagedAttention to increase efficieny of rejection sampling by 2x.

Gemma 3, March ‘25#

  • Multimodal, long context, multilingual, trained with knowledge distillation
  • Architecture - GQA, interleaved local-global attention layers (in 5:1 ratio) to handle long context efficiently. Local layers operate over a shorter span (1024 tokens) while the global layers attend to the full context length. This helps reduce the memory footprint of Key-Value (KV) cache.
    • Vision
      • 400M SigLIP encoder which is a ViT trained with a variant of the CLIP loss. Takes as input square images resized to 896x896 and is finetuned on data from visual assitant tasks.
      • Pan & Scan (P&S) - segments images into non-overlapping crops of equal size, covering the whole image, and then resize them to 896x896 pixes to pass to the encoder.
  • Parameters - 4 sizes, 1B, 4B, 12B, 27B. 4B and above are multimodal.
  • Context length - 1B supports 32K tokens, others 128K tokens. The RoPE base frequency is increased to 1 million for global attention layers while remaining at 10K for local layers.
  • Tokenizer - same as Gemma 2, a SentencePiece tokenizer with split digits, preserved whitespace, and byte-level encodings with a vocab size of 262k entries.
  • Data - different for each size. 1B -> 2T tokens, 4B -> 4T, 12B -> 12T, 27B -> 14T
  • Training
    • Pre-training - uses TPU, uses knowledge distillation from larger, more capable models (presumably Gemini). Sample 256 logits per token, weighted by teacher probabilities, that the student learns via cross-entropy loss.
    • Post-training - Knowledge distillation from a large IT teacher, RL finetuning phase based on improved versions of BOND, WARM and WARP.
    • To train a small model, it is preferable to distill from a smaller teacher, possibly because the regularization effect of using a worse teacher surpasses the benefit of using a better teacher.

Alibaba Qwen#

Qwen2.5, ‘24#

  • Architecture - GQA, RoPE, SwiGLU. Qwen2.5-1M uses a sparse attention mechanism to manage computational cost. Also supports MoE.
  • Context Length - 32K tokens. For 1 million tokens, they use training-free length extrapolation methods to scale models trained on 256k contexts up to 1M
  • Tokenizer - vocab size of 150K
  • Data - 7T high quality tokens
  • Training
    • Pre-training - simply increasing data volume by relaxing quality didn’t help
    • Post-training - SFT, RL
      • for 1M model, synthetic long data was synthesized using Qwen-Agent framework
      • Two-Stage SFT: 1/ short instruction data (up to 32K tokens), 2/ mix of short and long data (up to 262K tokens)
      • Short-Sample RL: only using short preference samples (up to 8K tokens)

Qwen3, April ‘25#

  • 36T tokens, using synthetic data from Qwen2.5-Math and Qwen2.5-Coder. Qwen3-4B can rival the performance of Qwen2.5-72B-Instruct.
  • Training
    • Pre-training in 3 stages.
      • Stage 1: 30T tokens with 4K context length for basic skills and general knowledge.
      • Stage 2: Increased the proportion of knowledge-intensive data and trained on 5T tokens.
      • Stage 3: High quality long-context data to extend the context length to 32K tokens.
    • Post-training in 4 stages.
      • Stage 1: long CoT cold start
      • Stage 2: reasoning-based RL using rule-based rewards
      • Stage 3: thinking mode fusion by instruction tuning on long CoT + instruction tuning data
      • Stage 4: general RL across more than 20 general domain tasks

DeepSeek v3#

  • Architecture - heavy on MoE. DeepSeek-V3 (large MoE with 671B params) uses Multi-Head Latent Attention (MLA) to improve efficiency by compressing KV cache using low-rank projections.
  • Context Length - 128K tokens. Two-stage context length extension process after pre-training applied using YaRN method to first extend to 32K and then to 128K
  • Tokenizer - BPE tokenizer with 100K vocab.
  • Data - ~15T token
  • Training
    • Pre-training
      • also uses a Fill-in-Middle (FIM) training objective (using a Prefix-Suffix-Middle format) at a 10% rate to improve performance on infilling tasks common in coding
      • FP8 training, bunch of work to improve MoE training bottlenecks (like DualPipe)
    • Post-training
      • SFT, using 1.5 million instruction-tuning examples. Uses reasoning-related data from DeepSeek-R1.
      • RL - uses GRPO
